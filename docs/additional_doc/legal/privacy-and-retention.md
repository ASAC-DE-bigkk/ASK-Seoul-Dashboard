# 개인정보·보존·삭제 운영 기준

이 문서는 현재 구현을 안전하게 운영하기 위한 기술 기준이며 법률 자문이나 확정된 개인정보 처리방침을
대체하지 않는다. 공개 운영 전 실제 사업자 정보, 처리 목적, 위탁사, 국외 이전, 법정 보존 기간,
정보주체 권리 절차를 관할 법률과 서비스 조건에 맞춰 검토한다.

## 처리 데이터와 목적

| 데이터 | 목적 | 저장 원칙 |
|---|---|---|
| 이메일, 닉네임, 마스킹 가능한 UUID | 계정 식별·로그인·운영 문의 | 내부 정수 ID는 외부에 노출하지 않음 |
| Argon2id 비밀번호 해시 | 인증 | 원문·복호화 가능한 값 저장 금지 |
| 약관 버전·동의 시각 | 동의 증빙 | 가입 시점의 버전 보존 |
| 세션/CSRF HMAC, IP·UA hash | 세션·보안 탐지 | 원문 token 저장 금지 |
| MFA salt/counter, 복구 코드 HMAC | 다중요소 인증 | TOTP 원문 seed·복구 코드 원문 저장 금지 |
| 역할·페이지 권한·이용권 만료 | 접근 제어·서비스 제공 | 최소 권한, 변경 감사 |
| 온톨로지·UI·차트 레이아웃 | 개인화 | 사용자 계정과 분리 가능한 FK |
| 모의 결제 요청·승인 메모 | 이용권 승인 | 실제 카드·계좌·결제수단 정보 수집 금지 |
| 감사 로그·알림 delivery | 보안·운영 추적 | secret/원격 응답 원문 기록 금지 |

Discord·Slack·Telegram 알림에는 승인에 필요한 최소 정보만 포함한다. 이메일 전체 주소, IP 원문,
세션 token, 비밀번호, MFA secret, webhook URL을 메시지에 넣지 않는다. 알림 채널이 국외 처리 또는
외부 위탁에 해당하는지는 실제 계약·리전에 맞춰 별도로 고지한다.

## 권장 보존 기준

아래는 기술 초기값이며 법정 의무와 서비스 정책이 우선한다.

| 범주 | 초기 기준 |
|---|---|
| 만료·소비된 인증 token/MFA challenge | 만료 후 7일 이내 정리 |
| 만료·폐기 세션 | 만료 후 30일 이내 정리 |
| 실패한 알림 delivery | 장애 분석 완료 후 90일 이내 삭제 또는 비식별 집계 |
| 보안·권한 감사 로그 | 최소 1년을 검토하되 목적·법적 근거에 따라 단축/연장 |
| 거절·탈퇴 계정 | 분쟁·법정 보존이 없으면 지체 없이 삭제 또는 비식별화 |
| 모의 결제 기록 | 서비스 운영상 필요한 기간만 보존; 실제 결제정보는 이 시스템에 저장하지 않음 |

`python3 scripts/cleanup_auth.py`는 기본 dry-run이며, 만료 token/challenge/session, 사용된 MFA
복구 코드, 종료된 알림 delivery와 만료 IP block을 좁은 범위로 정리한다. 사용자 삭제·감사 로그 삭제는
자동화되어 있지 않으므로 승인·백업·법정 보존 확인 후 별도 운영 절차로 수행한다.

MFA 강제 초기화 사유에는 본인 확인 방법과 업무상 근거만 적고, 신분증 번호·비밀번호·복구 코드·
민감한 상담 원문을 기록하지 않는다.

## 정보주체 요청과 계정 종료

1. 요청자의 본인 여부를 기존 로그인, 이메일 인증 또는 별도 운영 확인으로 검증한다.
2. 계정 UUID를 기준으로 사용자 데이터, 권한, 환경설정, 레이아웃, 결제 요청, 감사 로그의 연결 범위를
   조회한다.
3. 법정 보존 대상과 보안 감사상 보존이 필요한 데이터를 분리하고 근거·만료일을 기록한다.
4. 삭제 시 활성 세션과 token을 먼저 폐기하고, FK cascade/SET NULL 동작을 검증한다.
5. 백업에서도 정해진 보존 기간이 끝난 뒤 사라지는지 확인한다.
6. 처리 결과와 예외 보존 항목을 요청자에게 고지하고 운영 감사 기록을 남긴다.

관리자 화면에서의 상태 변경은 계정 삭제를 대신하지 않는다. `suspended`/`rejected`는 접근 차단 상태이며,
개인정보 삭제 요청에는 별도의 삭제·비식별화 절차가 필요하다.
