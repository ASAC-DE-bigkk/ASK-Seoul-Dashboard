# Charts Studio 개발 의도 — 대분류 › 중분류 › 소분류

Charts Studio 를 만들며 실제로 코드에 반영한 결정들을 계층으로 정리한다.
각 항목은 "왜 그렇게 했는가"가 기준이며, 구현 위치를 함께 적어 코드와 문서가 어긋나면
코드를 따라가되 이 문서를 갱신한다.

---

## A. 격리 (Isolation) — "본체를 오염시키지 않는다"

### A-1. 번들 경계
- **A-1-1. 백엔드 번들**: 차트 로직 전부가 `app/charts/` 안에 있다(온톨로지·SQL 빌더·Trino 실행기·레이아웃 저장·라우터·Pydantic 계약). 폴더를 지우면 기능이 통째로 사라지는 구조.
- **A-1-2. 프론트 번들**: 화면 전부가 `app/static/charts/` 안에 있다(HTML·CSS·JS 4모듈·지도 GeoJSON).
- **A-1-3. 본체 접점 최소화**: 기존 코드 변경은 `app/main.py` 라우터 include + `/charts` 라우트(9줄), 마켓플레이스 사이드바 진입 아이콘(1줄)뿐. 카탈로그 API·화면은 손대지 않았다.

### A-2. 데이터 접점
- **A-2-1. 스냅샷 재사용**: 소스 목록·스키마는 본체가 이미 서빙하는 `snapshot/catalog_snapshot.json` 에서 파생 — 카탈로그와 차트가 같은 진실을 본다.
- **A-2-2. 런타임 상태 격리**: 사용자 레이아웃은 RDB `auth_dashboard_layouts`에 사용자별로 저장하고,
  질의 캐시(`cache/`)는 `app/charts/data/` 아래 gitignore 런타임 파일로 둔다. 커밋되는 기본 레이아웃은 시드뿐.

## B. 온톨로지 — "도표는 컬럼이 아니라 의미에 묶인다"

### B-1. 의미역(role) 어휘 (`ontology.py`)
- **B-1-1. role 집합**: `time`(연/월/일/월중), `sequence`(경과연차·시간대 등 진행축), `ordinal`(순위처럼 순서는 있지만 시간이 아닌 축), `geo_gu/geo_gu_code/geo_dong/geo_dong_code/geo_legal_code/geo_legal_dong/geo_sido/geo_country/geo_lat/geo_lng`, `category`, `measure`, `id`.
- **B-1-2. 자동 추론**: 이름 사전(`NAME_ROLES`) → 날짜/시각·코드·순번 패턴 → 식별자 패턴 → SQL 타입 순으로 판정. `hr/hour/dow/rank`는 진행축, `nx/ny`는 기술 식별자, varchar `*_date`도 시간축으로 보정해 숫자라는 이유만으로 측정값을 만들지 않는다.
- **B-1-3. 측정값 계약**: 필드마다 `preferred_agg`, `additive`, `cumulative_safe`, `allowed_aggs`, `recommendation_priority`를 계산한다. 건수는 합계, 온도·확률·coverage·미세먼지·거리·속도·혼잡도는 평균을 우선하며 비가산 필드에서는 합계 선택지를 제거한다. 공간 가산성과 시간 누적 가능성은 별개이고, 시간 누적은 필드명 추측이 아니라 검증된 개·폐업 flow 소스 allowlist만 허용한다.
- **B-1-4. 안전하지 않은 일반 집계 차단**: long-form 날씨의 `fcst_value_num/value_num`은 category에 따라 단위가 바뀌고, 풍향각은 산술평균이 틀리며, 적재/수집 시각은 분석 시간축이 아니다. 이 필드는 `chartable=false`로 슬롯에서 제외하되 필터에는 사용할 수 있다.
- **B-1-5. 큐레이션은 힌트만**: `CURATED` 는 한국어 라벨·기본 도표 제안만 얹는다. 구조(role) 판정의 정본은 자동 추론 — 큐레이션이 없어도 모든 기능이 동작해야 한다.

### B-2. 슬롯 계약 (chart type = 필요 role 선언)
- **B-2-1. 도표 타입 정의**: 각 타입은 "슬롯(이름·허용 role·필수 여부)"만 선언한다(`CHART_TYPES`). 예: 지도 = 지역 role 1 + measure 1.
- **B-2-2. 지원 판정**: 슬롯-role 교집합만 보지 않고 필수 슬롯마다 **서로 다른 실제 필드**를 배정할 수 있는지 이분 매칭으로 계산한다. X=Y 산점도, 같은 축을 두 번 쓰는 히트맵은 지원으로 표시되지 않는다.
- **B-2-3. 서버가 정본**: 슬롯 계약은 `/api/v1/charts/meta` 로 프론트에 내려간다. 프론트에 계약 사본을 두지 않는다.
- **B-2-4. 행 수는 파생 측정값**: 물리 measure가 없는 문화 행사·스포츠 일정도 가짜 필드를 만들지 않고 `count(*)`로 날짜/장소/지역별 건수를 그린다. count일 때만 값 슬롯을 생략할 수 있다.
- **B-2-5. 선택 계약과 렌더 계약 분리**: 개인 정책으로 숨긴 도표는 선택 목록에서만 빠지고 `chart_contracts`에는 남는다. 정책 변경 전에 저장한 타일이 갑자기 “알 수 없는 도표”가 되지 않는다.
- **B-2-6. 도표별 수학 제약**: 원형은 부분의 합이 전체가 되는 `sum/count`만, 누적 경주는 `cumulative_safe` 흐름의 `sum`만 허용한다. 선의 시간축에는 단순 category를 넣지 않는다.

### B-3. 변화(드리프트) 흡수
- **B-3-1. role 폴백**: 저장된 바인딩 필드가 사라지면 같은 role 의 다른 필드로 재바인딩하고 타일에 표기(`resolveBindings`). 차트 저장물은 {type, source, bindings, agg, filters, options} 뿐이라 렌더 시점마다 재해석된다.
- **B-3-2. 타입 드리프트 안전 필터**: 물리 타입이 스냅샷과 달라져도 깨지지 않게, 문자열 비교는 `cast(col as varchar)`, 숫자 비교는 `try_cast(col as double)` 로 조립(`querybuilder._condition`). 실제 사례: `cohort_y` 가 varchar→integer 로 바뀐 것을 개발 중 흡수.
- **B-3-3. 값 라벨 사전**: 코드값(개업/폐업, 대분류, 업력 밴드)은 `VALUE_LABELS` 로 표시만 번역 — 원본 값은 바꾸지 않는다.
- **B-3-4. 필터 계약 공유**: role별 `allowed_filter_ops`를 SourceDetail로 내려 UI와 querybuilder가 같은 연산자 목록을 쓴다. 숫자 role은 유한한 숫자/숫자 문자열만 `try_cast(... as double)` 비교로 정규화하고 `like`나 문자열 대소 비교를 거부한다.

### B-4. 자동 추천 (`recommend.js`) — "온톨로지가 있으니 추천은 공짜다"
- **B-4-1. 규칙은 role 의 함수**: 도표 추천(`RECO.types`)과 바인딩 조합(`RECO.combos`)은 (필드 role, 슬롯 계약, 값 라벨 사전)만 입력으로 받는 순수 함수 — 테이블·컬럼명 하드코딩 없음. 새 소스가 실리면 그 시점의 데이터 모양으로 즉석 재계산된다.
- **B-4-2. 보편 문법 매핑**: 시간축→선(순환월은 히트맵), 시간축×범주→타임랩스 경주, 범주→막대, 소분류(값 라벨 사전 등재=저카디널리티 확정)→도넛, 측정값 2개→산점도, 지역 role→해당 지도, 좌표→점밀도, 축 없는 숫자→스탯.
- **B-4-3. 이름 패턴 → 집계 제안**: 건수형(`cnt/count/n_/active…`)은 합계, 비율형(`rate/ratio/lq/survival…`)은 평균 — D-2 의 왜곡 방지 규칙과 일관.
- **B-4-4. 추천의 어조**: 강조는 배지+파란 테두리, 이유는 호버 툴팁에 **사람 말투**로("계절이 만드는 무늬는 히트맵이 제일 잘 그려요") — 근거는 항상 실제 필드 라벨을 인용해 컬럼 형태에 접지시킨다.
- **B-4-5. 원클릭 적용**: 연결 단계의 추천 조합 칩은 바인딩·집계·옵션을 폼에 주입하고 미리보기를 자동 실행 — 수동 수정 시 선택 표시가 해제된다(사용자 의사가 항상 우선).
- **B-4-6. 분석 시각 우선**: `forecast_at/event_at/hour_at` 같은 분석 시각을 revision/published/collected 같은 기술 시각보다 먼저 추천한다. 구조·품질 진단 필드도 기본 측정값 후보의 뒤로 보낸다.
- **B-4-7. 실데이터 가용성 게이트**: 소스 선택 시 화이트리스트 필드별 `count(field)`를 한 질의로 확인한다. null 아닌 값이 0인 필드는 슬롯·필터 선택지에서 제거하고, 남은 필드로 도표 지원 목록을 다시 계산한다. stale 캐시나 Trino 장애는 숨기지 않으며 미리보기의 전부-null 방어를 마지막 안전망으로 둔다.
- **B-4-8. 최소 표현 가능성**: 1행 요약 소스는 통계·표만 제공한다. 선·면적·레이스는 유효 측정값이 있는 진행 지점이 최소 2개일 때만 렌더 성공으로 판정한다.

## C. 데이터 경로 — "안전하게 묻고, 정직하게 답한다"

### C-1. 질의 안전 (`querybuilder.py`)
- **C-1-1. 식별자 화이트리스트**: 소스·필드는 레지스트리에 실재하는 이름만 SQL 에 들어간다(그 외 400). 집계·연산자도 고정 집합.
- **C-1-2. 값 이스케이프**: 리터럴은 `''` 이스케이프 + 제어문자 거부. Trino REST 가 파라미터 바인딩을 안 주는 환경에서의 차선책.
- **C-1-3. 읽기 전용 형태 보장**: SQL 은 `select … from <registry relation>` 형태로만 조립된다 — 임의 문장이 낄 자리가 없다.

### C-2. Trino 실행 (`trino.py`)
- **C-2-1. 표준lib 만**: urllib 로 REST 프로토콜(nextUri 폴링)을 직접 따른다 — 의존성 추가 없이 이식성 유지.
- **C-2-2. 프로토콜 준수**: 503 은 실패가 아니라 재시도 신호(0.1s 후 같은 URI), 포기 시 `DELETE nextUri` 로 서버 질의를 남기지 않는다. 전체 데드라인 120s.
- **C-2-3. 캐시 계층**: 결과는 디스크 캐시(TTL 기본 600s). Trino 다운이면 **stale 캐시로 응답하되 mode 로 정직하게 표기** — 죽은 화면보다 낡은 데이터가 낫고, 낡았음을 숨기지 않는다.
- **C-2-4. force 우회**: '다시 조회'와 자동 갱신은 신선 캐시를 건너뛰고 라이브 재질의(`force=True`).
- **C-2-5. 비싼 질의 보호**: availability도 일반 chart query와 같은 사용자별 제한을 적용한다. 같은 SQL의 동시 cold-cache 요청은 singleflight lock으로 한 번만 실행해 대형 Gold의 중복 전수 스캔을 막는다.

### C-3. 한계의 가시화
- **C-3-1. 행 상한**: 서버 상한 5,000행. 상한에 닿으면 타일에 "행 상한 도달" 경고 — 조용한 절단 금지.
- **C-3-2. SQL 투명성**: 응답에 실행 SQL 을 포함, 타일 노트 툴팁으로 확인 가능.
- **C-3-3. 에러 규약**: 본체와 동일한 RFC 7807 problem+json (400 스펙 오류 / 502 질의 실패 / 503 접속 불가).

## D. 시각화 규칙 — "읽히는 도표" (dataviz 스킬 기준 적용)

### D-1. 색
- **D-1-1. 검증된 고정 팔레트**: 카테고리 8슬롯 고정 순서(`#2a78d6 #008300 #e87ba4 #eda100 #1baf7a #eb6834 #4a3aa7 #e34948`) — 흰 서피스 기준 CVD 검증기 통과. 9번째 시리즈부터는 새 색을 만들지 않는다.
- **D-1-2. 색-의미 고정**: `opened(개업)=파랑, closed(폐업)=주황` 값 기준 고정(`VALUE_COLORS`) — 정렬·필터가 바뀌어도 색이 뒤바뀌지 않는다. '기타'는 항상 중립 회색 `#b3bac7`.
- **D-1-3. 순차 램프**: 지도·히트맵의 크기 인코딩은 파랑 단일 색상 램프(밝→어두움). 텍스트는 잉크 토큰만 쓴다(시리즈 색으로 글자 쓰지 않음).

### D-2. 데이터 왜곡 방지
- **D-2-1. 결측 ≠ 0**: 피벗의 빈 셀은 `null` — 코호트 우측검열 구간이 0% 로 추락하는 왜곡을 막는다(선은 거기서 끝난다).
- **D-2-2. '기타' 접기 조건**: 시리즈 9개 초과 시 sum/count 에서만 '기타'로 합산. avg 등 비가산 집계는 "평균의 합"이 되므로 접지 않고 상위 8개만 표시 + 개수 표기.
- **D-2-3. 자연 순서 우선**: 축 값이 숫자(월·연차)거나 코드형 순서(`0_lt1y…`)면 값 크기 정렬보다 자연 순서로 — 계절성·업력 밴드가 뒤섞이지 않는다.
- **D-2-4. 산점도 count 금지**: X·Y 가 같은 값으로 붕괴(대각선)하므로 UI 에서 제외 + 빌더에서 avg 로 방어.
- **D-2-5. 시드의 통계 정직성**: 비가중 평균을 쓰는 차트는 제목에 명시("단순평균"), 소표본 왜곡은 필터(`n_closed ≥ 100`)로 차단, 코호트 곡선은 단일 업종(외식업)으로 한정해 정확한 비율만 그린다.
- **D-2-6. 전 렌더러 결측 보존**: 선·막대·산점도·히트맵·지도·스탯·레이스 모두 null을 숫자 0으로 강제 변환하지 않는다. 없는 관측은 gap/제외/`—`로 남기고 실제 0만 0으로 그린다.
- **D-2-7. 실측 기반 축 자율성(선언 아님)**: '숫자형=측정값' 규칙의 두 예외를 **실측**으로만 연다. ① 저카디널리티 개방 — extract 가 잰 `approx_distinct ≤ 50` 인 measure 는 category 축 슬롯에 설 수 있다(`groupable`, 등급·개수형 컬럼). ② 구간 축 — binnable 슬롯(막대/원형/히트맵/테이블)에 measure 를 놓으면 구간 폭(`bins[슬롯]`, 기본값은 실측 min/max 에서 1·2·5·10 단위 제안)으로 `floor(값/폭)*폭` 그룹핑한다(히스토그램형). 두 경우 모두 축에 묶인 measure 는 그룹 키라서 값 집계 제약(비가산 sum 금지 등)을 받지 않는다 — 제약은 '집계되는 슬롯'(value/x/y)에만 적용. 서버 `field_matches_slot`·프론트 `fieldMatchesSlot` 이 같은 규칙 하나를 공유한다.

### D-3. 지도
- **D-3-1. 코드 체계 구분(중요)**: gold 데이터의 지역 코드는 전부 **MOIS(행안부)** 체계, 반면 seoul_gu/seoul_dong GeoJSON 의 원 code 속성은 **KOSTAT(통계청)** 체계다. 둘을 섞으면 '다른 구'에 칠해진다 — 코드 매칭은 MOIS 값이 있는 지도에서만 허용: 자치구=이름 역매핑(`MOIS_GU`), 법정동=EMD_CD 자체가 MOIS, 행정동=`scripts/assign_mois_codes.py` 가 폴리곤에 병기한 `mois_code`(참조 `bronze_ref_admin_dong` 실측 매칭, 421/423). KOSTAT code 는 여전히 매칭에 쓰지 않는다.
- **D-3-2. 동명이동 처리**: 등록 시 중복 이름은 "신사동·강남구" 식으로 유일화. 이름으로 들어온 모호한 행은 양쪽에 이중으로 칠하지 않고 **제외 + 개수 표기**. 코드로 들어온 행은 동명이동도 정확히 분리해 칠한다.
- **D-3-3. 커버리지 정직성**: 모든 지도 타일은 `매칭 N/M` 을 표기 — 얼마나 못 붙었는지 숨기지 않는다. 2013 경계 자산의 개편 미반영(상일1동 등)도 이 카운터에 드러난다.
- **D-3-4. 식별=코드·표기=한글(전 도표 공통)**: 코드/이름(en/ko) 동반 컬럼이 있으면 집계 GROUP BY 는 항상 코드다 — 프론트 `effectiveBindings` 가 이름 바인딩을 `id_field` 로 승격한다(저장물 불변, 지도 밖 막대/파이/테이블에도 적용). 화면 표기는 서버 `value_labels`(스냅샷 `code_labels` 실측 + 정적 큐레이션)가 코드를 최말단 한글 라벨로 되돌린다.

### D-4. 마크·상호작용
- **D-4-1. 마크 스펙**: 막대 상단 4px 라운드·누적 세그먼트 흰 경계, 선 2px, 산점 ≥8px, 그리드/축은 후퇴색.
- **D-4-2. 툴팁 기본 탑재 + XSS 방어**: 모든 도표에 호버 툴팁. 커스텀 formatter 의 데이터 유래 문자열은 전부 escapeHtml — 행 값에 악성 HTML 이 있어도 실행되지 않는다.
- **D-4-3. 퍼센트 휴리스틱**: 필드명이 rate/ratio/share/survival/율 계열이고 값이 ≤1.5 면 % 로 표기.
- **D-4-4. 타임랩스 명시 제어**: 캔버스 전체 클릭이라는 숨은 동작 대신 이전/다음 프레임, 재생/정지, 0.5×~2× 속도, 현재 프레임을 실제 버튼·select로 제공한다. 속도 변경은 즉시 스케줄을 바꾸고 pause/dispose 시 타이머를 제거한다.

## E. UX / 레이아웃 — "보는 모드와 고치는 모드를 분리한다"

### E-1. 편집 모드 토글
- **E-1-1. 평시 고정**: 일반 화면에서 타일은 움직이지 않는다. 배치 변경은 **레이아웃 변경** 버튼을 눌러야만 가능(요구사항이자 오조작 방지).
- **E-1-2. 명시적 저장**: 드래그·추가·삭제는 **레이아웃 저장**을 눌러야 영속. 취소로 되돌리기, 미저장 이탈 시 경고.
- **E-1-3. 편집 시각 신호**: 노란 배너 + 모눈 배경 + 타일 액션 아이콘 노출로 모드를 명확히 구분.

### E-2. 페이지(사이드탭)
- **E-2-1. 다중 레이아웃**: 페이지 추가/전환/우클릭(순서 위·아래, 이름 변경, 복제, 삭제). 목록이 길어지면 **목록만** 스크롤.
- **E-2-2. 경합 방어**: 페이지 연타 전환 시 세대 토큰으로 늦은 응답을 폐기 — 다른 페이지 위에 저장해 덮어쓰는 사고를 차단.
- **E-2-3. 원자적 페이지 확정**: 페이지 조회가 끝나기 전에는 `pageId`를 바꾸지 않고 편집·저장을 잠근다. 편집 취소 재조회와 저장도 같은 직렬화 경로를 사용해 이전 페이지 응답이 새 페이지를 덮지 않는다.

### E-3. 갱신 체감
- **E-3-1. 무깜빡임 자동 갱신**: 주기 갱신은 스피너로 화면을 가리지 않고 데이터 도착 시 교체. 수동 조회는 스피너로 피드백.
- **E-3-2. 상태 배지**: live/cached/stale 를 타일마다 표기, stale 발생 시 톱바 펄스가 경고색.
- **E-3-3. 크기 안정성**: ResizeObserver 로 어떤 시점에 그려져도(캐시 즉답 포함) 실제 타일 크기로 수렴.

### E-4. 구성 드로어
- **E-4-1. 막다른 선택지 제거**: 실제 필드 조합이 가능한 소스·도표만 목록에 표시하고 추천 순으로 정렬한다. 역할이 없거나 중복 필드 없이는 구성할 수 없는 항목을 disabled 장식으로 남기지 않는다.
- **E-4-2. 비동기 최신성**: 소스 상세·미리보기·타일 재조회마다 세대 토큰을 두고 늦은 응답을 폐기한다. 소스를 바꾸면 이전 소스의 필터·집계·제목을 함께 초기화한다.
- **E-4-3. 적용 전 실데이터 확인**: 현재 초안과 일치하는 미리보기가 성공하고 실제 측정값이 1개 이상 유효한 경우에만 추가/적용한다. 실패·0행·전부 null·음수 원형 초안은 레이아웃에 넣지 않는다.
- **E-4-4. 입력 손실 방지**: 검색은 input DOM을 교체하지 않아 연속 입력 포커스를 보존하고, 작성 중 닫기에는 확인을 받는다. 드로어는 dialog/inert/focus trap 계약을 사용한다.
- **E-4-5. 작은 화면 기본 경로**: 900px 이하에서도 톱바의 페이지 select·추가·`⋯` 관리 메뉴로 전환/이름/복제/순서/삭제 기능을 잃지 않는다.
- **E-4-6. 필터 추측 최소화**: 연산자는 한국어로 표시하고 값 사전에 있는 열은 실제 코드/라벨 선택창을 쓴다. 빈 값은 프론트와 querybuilder 양쪽에서 거부하고 목록·범위 입력 규칙을 바로 아래 안내한다.

## F. 검증 문화 — "고치면 기계로 다시 증명한다"

- **F-1. 브라우저 셀프테스트**: `/charts?selftest=1` — 사용자 시드는 수정하지 않고 고유 이름의 임시 페이지에서 CRUD를 수행한 뒤 `finally`로 삭제·원래 순서를 복구한다. 3페르소나(검색 연타, tooltip 전환, 원클릭 추천), 6개 도메인의 실제 드로어→availability→자동 바인딩→미리보기 렌더, 중복 축 방지, count-only 소스, race 컨트롤, null 보존을 자동 검증한다(탭 제목으로 판정).
- **F-2. 헤드리스 스크린샷 루프**: Chrome `--headless --screenshot` 으로 화면을 직접 보고 고치는 반복 — hidden 무시, 축소 렌더, 정렬 오류가 이 루프에서 잡혔다.
- **F-3. 개발용 오버라이드**: `?page=<id>`(딥링크), `?uidemo=1|drawer|bind`(편집/드로어 상태 재현), `?refresh=<초>`(자동 갱신 가속 검증).
- **F-4. 다관점 리뷰 반영**: 정확성·프론트·보안·시각화 4관점 멀티에이전트 리뷰 + 반박 검증에서 확정된 14건(critical 1·major 13)을 전부 수정 — 위 D-2·D-3·C-2 의 상당수가 그 산물이다.
- **F-5. 서버 계약 회귀**: `tests/test_charts_ontology.py`가 모든 6개 도메인·59개 스냅샷 Gold의 지원 타입을 순회해 실제 서로 다른 바인딩, 집계 제약, 시드 레이아웃, querybuilder 거부 규칙을 검증한다.
